# Prototype Handoff Guide (Codex / Claude Code)

This guide helps an autonomous coding agent quickly finish a **working prototype** of Hawkeye Flutter with the least ambiguity.

## 1) Project Snapshot

- **Framework**: Flutter
- **Backend**: Firebase Auth + Firestore + Storage
- **Security model**: Client-side encrypted payloads for location/place data
- **Current app flow**:
  - `AuthGate` decides login vs. app shell.
  - `LoginScreen` handles sign in/up.
  - `HomeScreen` handles circles, places, and location posting.

## 2) Current Code Map

- App bootstrap: `lib/main.dart`, `lib/src/app.dart`
- Auth UI and flow: `lib/src/ui/screens/auth_gate.dart`, `lib/src/ui/screens/login_screen.dart`
- Primary product UI: `lib/src/ui/screens/home_screen.dart`
- Domain models: `lib/src/models/*.dart`
- Data repositories: `lib/src/repositories/*.dart`
- Infra services:
  - Auth: `lib/src/services/auth_service.dart`
  - Crypto: `lib/src/services/crypto_service.dart`
  - Storage: `lib/src/services/storage_service.dart`

## 3) Definition of "Working Prototype"

Use this checklist as the target acceptance criteria:

1. User can register and sign in with email/password.
2. User profile document is created in Firestore.
3. User can create or join at least one circle.
4. User can add a place and see it in the UI.
5. App can post one mock encrypted location update and fetch/display recent updates.
6. Avatar upload works for at least one image to Firebase Storage.
7. No crash on cold start with an authenticated user.

## 4) Recommended Build Order for Agents

1. **Stabilize startup**
   - Validate Firebase initialization and `AuthGate` behavior.
2. **Lock auth UX**
   - Ensure register/sign-in errors show clear messages.
3. **Ensure user document lifecycle**
   - On first sign-in, create default user profile if missing.
4. **Finish circle CRUD basics**
   - Create, list, and join by code.
5. **Complete place flow**
   - Add place form + list rendering + persistence.
6. **Validate encrypted location flow**
   - Encrypt on write, decrypt on read, and handle corruption gracefully.
7. **Add happy-path QA script**
   - Script/manual checklist for full end-to-end smoke test.

## 5) Agent Task Board (copy/paste into issue tracker)

- [ ] Add robust loading and empty states in `HomeScreen`.
- [ ] Add form validation + friendly error text in `LoginScreen`.
- [ ] Add repository-level guardrails for null/missing Firestore fields.
- [ ] Add a reusable snackbar/toast helper for user feedback.
- [ ] Add one `integration_test/` happy-path smoke test (auth → create circle → add place).
- [ ] Add seed/debug action in dev mode for mock encrypted locations.

## 6) Suggested Environment Variables / Secrets Handling

- Do **not** hardcode API keys outside `firebase_options.dart` generated by FlutterFire.
- Keep sensitive runtime keys in secure storage (already modeled by `CryptoService`).
- Use separate Firebase projects for `dev` and `prod`.

## 7) Smoke Test Script (Manual)

1. Launch app on emulator/device.
2. Register a new user.
3. Create circle "Family".
4. Add one place (e.g., "Home").
5. Upload avatar.
6. Send mock location.
7. Sign out and sign in again.
8. Verify circle/place/location still render.

## 8) Common Failure Modes

- **Permission denied (Firestore/Storage)**: Security rules are incomplete.
- **User signs in but sees blank state forever**: Listener stream or mapping error in repository.
- **Decryption failure**: Key rotation/reset mismatch with encrypted payload schema.
- **Avatar upload fails silently**: Storage path/rules mismatch or missing metadata.

## 9) Done Criteria for Handoff

A PR is considered prototype-ready when:

- All checklist items in section 3 are met.
- Firebase setup steps in `docs/FIREBASE_SETUP_STEP_BY_STEP.md` are fully applied.
- README quick-start runs successfully on a fresh machine.
